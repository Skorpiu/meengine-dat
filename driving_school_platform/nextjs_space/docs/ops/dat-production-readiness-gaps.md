# DAT production / public demo — readiness gaps

Concise gap audit after **hosted deploy + basic smoke** (see [production-smoke-baseline.md](./production-smoke-baseline.md)). Use this to pick the **next 3–5** work batches—not as a live status page.

**Controlled first B2B client:** see [production-readiness-cutline.md](../../../../docs/architecture/production-readiness-cutline.md) (**DEC-032**) — DAT core is production-ready for invite-only, no public signup, no live billing. This gaps doc remains relevant for **portfolio/demo** posture and residual engineering polish.

Do **not** put credentials, customer emails, URLs with embedded secrets, or billing identifiers in tickets or git.

---

## What already looks solid (operational)

- **CI** — pipeline green on shipped commits; **GitLab** runs the same canonical gate as local development — **`pnpm -C driving_school_platform/nextjs_space check`** (see root `.gitlab-ci.yml`) — so lint, typecheck, tests, and build stay aligned with the developer workflow.
- **Hosting** — Vercel production deploy serving the app; **`GET /api/health`** OK; optional `pnpm smoke:health` pattern documented.
- **Split hosts** — tenant-facing app vs platform operator host model documented ([production-host-split.md](./production-host-split.md)); smoke baseline reflects successful login and core routes for admin / instructor / student / **PLATFORM_ADMIN** on the intended origins ([production-smoke-baseline.md](./production-smoke-baseline.md)).
- **Controlled Full Showcase demo (operational)** — **`DAT Demo — Full Showcase`** on **`demo.meengine.io`**: private personas, Full Showcase profile (including vehicle management UI), intentional **`DEMO_WRITE_SANDBOX_ENABLED=true`** on Vercel Production, per-type create quotas validated, Schedule Map refresh and type colors validated, signup disabled for demo org, instructor scope without admin tabs. Operator flow: [client-demo-runbook.md](./client-demo-runbook.md#current-validated-demo-status).
- **Demo isolation foundation** — `Organization.isDemo`, demo route/mutation guards, **controlled write sandbox** (`DEMO_WRITE_SANDBOX_ENABLED`, lesson/vehicle create quotas — [client-demo-runbook.md](./client-demo-runbook.md#controlled-demo-write-sandbox)), **manual sandbox reset** (`pnpm demo:sandbox:reset` — [client-demo-runbook.md](./client-demo-runbook.md#reset-demo-sandbox-after-a-meeting)), **daily cron sandbox reset** (`GET /api/cron/demo-sandbox-reset` with `CRON_SECRET` — [client-demo-runbook.md](./client-demo-runbook.md#automatic-daily-demo-sandbox-reset)), and read-only **`pnpm demo:readiness`**, **`pnpm demo:features:check`**, and **`pnpm demo:client-ready`** aligned with showcase policy ([public-demo-policy.md](./public-demo-policy.md), [public-demo-seed-reset.md](./public-demo-seed-reset.md), [public-demo-feature-showcase.md](./public-demo-feature-showcase.md)).
- **Mutation / control-plane guards (tenant demo)** — destructive and tenant admin control-plane writes gated for marked demo orgs (same policy doc); **not** a substitute for a separate demo database or operator-only platform discipline.
- **Demo seed / reset runbook** — documented expectations, personas without passwords in git, **`pnpm demo:reset:dry-run`** for org validation ([public-demo-seed-reset.md](./public-demo-seed-reset.md)).
- **Supabase RLS (internal `public` tables)** — Security Advisor–flagged tables such as `billing_events`, `entitlement_grants`, and `organization_domains` have **RLS enabled** without permissive `anon`/`authenticated` policies (migration + policy: [supabase-data-api-policy.md](./supabase-data-api-policy.md)). **Future:** optional hardening such as removing `public` from exposed Data API schemas or a dedicated `api` schema if PostgREST is adopted.
- **Public portfolio messaging** — root README and [public-portfolio-access.md](./public-portfolio-access.md) set honest expectations (no embedded credentials, no live billing claims).
- **Demo tier profiles (operator)** — `lib/demo/demo-tier-profiles.ts` plus `DEMO_SHOWCASE_PROFILE` on **`pnpm demo:showcase:configure`** give repeatable **basic / premium / full-showcase** key sets without auto-creating orgs ([public-demo-feature-showcase.md](./public-demo-feature-showcase.md)).
- **Signup / auth surface (phase 1 — addressed)** — Demo orgs: **`POST /api/signup`** → **403** `demo_signup_disabled`. Non-demo: **public signup disabled by default** unless **`PUBLIC_SIGNUP_ENABLED=true`**. Register UI shows stable messages; login unchanged (NextAuth credentials).
- **Auth email (DAT_3.5 — addressed)** — Postmark selected and implemented; **password reset** and **email verification** implemented; production Postmark validated. Auth rate-limit foundation implemented. See [auth-email-production-readiness-checklist.md](./auth-email-production-readiness-checklist.md). Status table: [signup-hardening-plan.md](../engineering/signup-hardening-plan.md#current-implementation-status).
- **School admin nav (DEC-026 — addressed)** — Settings removed from school admin navbar; **Plan** (`/admin/license`) read-only for school admin. `/admin/settings` operator/internal direct URL only.
- **Admin lessons GET** — **`GET /api/admin/lessons` is read-only** (no automatic lesson cleanup on read). **Calendar** `from`/`to` queries enforce a **90-day max range** (`lib/lessons/calendar-range.ts`); row pagination may still be added later if needed. **Operational cleanup** remains **POST** `/api/admin/cleanup` (explicit, tenant-scoped, demo-guarded).
- **Lesson calendar range guardrail** — **`validateLessonCalendarRange`** applies to **admin**, **instructor**, and **student** lesson calendar GETs (`from`/`to`); invalid or **>90-day** windows return **400** with stable `code` fields. **Single-day** ranges (`from` === `to`, Schedule Map **day** view) are valid.
- **Lessons route refactor** — **Substantially complete / currently addressed** per [lessons-route-refactor-plan.md](../engineering/lessons-route-refactor-plan.md): query module, mappers, create/update-delete services, shared calendar range (admin/instructor/student), list + detail DTO minimization (`LESSON_LIST_SELECT`, `LESSON_DETAIL_SELECT`), nested user sanitization (API + SSR), dashboard/EXAMS client alignment, and **`lesson-response-contract`** tests. **Real follow-ups (optional):** API envelope unification (RHC-001), E2E beyond integration tests, row pagination inside the 90-day window if payloads grow.
- **Demo practical lesson readiness** — operator script **`pnpm demo:practical:configure`** links demo instructor qualified categories for `DRIVING` lessons without changing production rules ([client-demo-runbook.md](./client-demo-runbook.md#prepare-practical-lesson-demo)).
- **Schedule Map refresh after lesson/exam create** — **Fixed:** day-view client refetch was failing because `validateLessonCalendarRange` rejected `from` === `to`; admin/instructor dashboards now refetch with the booked date and show new lessons/exams without a tab switch (`schedule-map-refresh-and-layout-fix`). **Schedule Map card layout** — compact chips (`truncate`, capped height) to avoid excessive scroll. **Type colors:** theory lesson green, driving lesson blue, theoretical exam (`THEORY_EXAM`) yellow, practical exam (`EXAM`) orange.
- **Practical exam booking (demo/admin)** — **Fixed** (`practical-exam-booking-fix`): exam dialogs normalize `vehicleId` to integer before POST (raw form payload failed Zod); exam dialog submit label **Book Exam** (was shared **Book Lesson** default).
- **Route handler consistency audit** — [route-handler-consistency-audit.md](../engineering/route-handler-consistency-audit.md) maps real `app/api` patterns. **Vehicles alignment (partial):** `assertVehicleTenantHost` + demo guards on status/maintenance via `lib/vehicles/vehicle-route-access.ts`; GET read-only on demo unchanged; POST sandbox unchanged. **Billing webhook (partial):** HTTP error responses sanitized (`lib/billing/webhook-http.ts`); provider signature validation still pending when a real PSP is in scope. **User management alignment:** tenant + demo guards and `PLATFORM_ADMIN` assignment block via `lib/users/user-route-access.ts`; list GET does not return `passwordHash`. **Response contract baseline (docs + tests):** [api-response-contract-baseline.md](../engineering/api-response-contract-baseline.md) — current shapes frozen for review; **wide envelope normalization still pending.**

## Prioritized checklist (detail)

### P0 — must fix before broad public sharing / open demo

| Gap                         | Why it matters                                                                                                                                                                                  | Direction (no implementation in this doc)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Demo vs production data** | Production DB may still hold **real** org and user data alongside the demo tenant. A public “try it” link on the **same** deployment without discipline still carries reputation and data risk. | **Mitigation in code (shipped):** `Organization.isDemo`, demo guards, controlled write sandbox, manual + daily sandbox reset — [public-demo-policy.md](./public-demo-policy.md), [client-demo-runbook.md](./client-demo-runbook.md#current-validated-demo-status). **Operational:** controlled Full Showcase on `demo.meengine.io` with private personas only. **Still open:** **separated demo database/deployment**, **`createdByDemoSandbox`** / seed baseline for finer deletes, full org destructive reset, billing webhook / platform onboarding policy follow-ups. **Access:** [public-portfolio-access.md](./public-portfolio-access.md). |
| **Credential policy**       | **PLATFORM_ADMIN** and **SUPER_ADMIN** secrets must never appear in README, issues, or “quick start” snippets ([platform-admin-runbook.md](./platform-admin-runbook.md)).                       | Document **who** gets which role; use vault + rotation; never ship demo PLATFORM_ADMIN passwords.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| **High-privilege exposure** | Sharing **one** production admin account for demos is a **destructive-data** and **reputation** risk (delete users, change license, onboarding on platform host).                               | If demos are required on prod-like infra, use **scoped** accounts and **runbooks** for reset/restore—not “the” admin.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
